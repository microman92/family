# A-12. Каркас первой фазы

Дата: 27.10.2026. Статус: принято.

## Решение

- Корневой `app/` содержит маршруты и адаптеры Next.js. FSD-компоненты находятся в `src/_app`, `src/_pages`, `widgets`, `features`, `entities`, `shared`. `src/app` и `src/pages` не создаются.
- Пустые разделы используют один FSD-слайс `_pages/section`: отдельные слайсы с бизнес-логикой появятся по мере реализации. Для каждого пустого маршрута сейчас создавать одинаковый компонент не требуется.
- Основные стили — SCSS Modules рядом с компонентами. Tailwind v4 подключён отдельным CSS-файлом и используется для shadcn/ui primitives. Семантические CSS-переменные общие для двух систем.
- Темой управляет `next-themes`: light/dark/system с сохранением в браузере. Тема не является пользовательскими данными сервера и работает до подключения аккаунта.
- Код RSC может входить в серверную часть через `index.server.ts`; серверные точки входа импортируют `server-only`. Next.js при сборке запрещает их попадание в клиентский граф.
- `dependency-cruiser` проверяет циклы, направление слоёв, cross-slice/deep imports и серверные доменные границы. ESLint проверяет React/Next/TypeScript.

## Граница первой фазы

Формулировка Gate 1 «авторизуемые маршруты» означает наличие каркаса будущих защищённых страниц. Реальная авторизация — фаза 2, RLS/guards — фаза 3. В первой фазе маршруты открыты, не читают пользовательские данные и не выполняют мутаций. Они прямо сообщают о недоступных функциях; гостевой просмотр не выдаётся за вошедшего пользователя.

Вход через Telegram, приглашения, отправка сообщений, финансовая логика и база данных не реализуются заранее. Кнопки входа отключены. Миграций и тестов RLS в этой фазе нет, поскольку нет пользовательских таблиц.

Секреты не нужны для запуска. `.env.example` содержит только названия переменных и пустые значения. `getPublicEnvironment` читает только публичный URL приложения на сервере; секреты не возвращаются в UI.

## Коммиты и ревью

Одна завершённая фаза — один осмысленный коммит после проверок. Формат: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`. PR описывает результат для пользователя, команды и реальные результаты проверок; шаблон лежит в `.github/pull_request_template.md`. Задачи отмечаются выполненными после проверки и сохранения в Git.

Будущие скрипты `test:db` и миграции добавляются вместе с реальной локальной БД во второй/третьей фазе. Фиктивные скрипты для прохождения CI не создаются.

## Инструменты и проверки

Версии зависимостей зафиксированы без диапазонов в `package.json` и `package-lock.json`. Адаптер форм использует совместимую ветку `@hookform/resolvers` 5. ESLint зафиксирован на 9.39.5: поставляемые с Next.js 16.4.3 плагины import/react/jsx-a11y ещё не объявляют совместимость с ESLint 10. npm предупреждает об окончании поддержки ESLint 9; обновление требует согласованной версии всей lint-конфигурации, без `--force`/`--legacy-peer-deps`.

E2E поднимает собственный production-сервер на порту 3107, не переиспользуя другие локальные серверы. Для Windows используется установленный Chrome; Linux CI устанавливает Chromium. Браузерные тесты в ограниченном Windows-окружении могут задерживать остановку сервера; запуск с разрешением управления дочерними процессами устраняет ограничение.

Источники настройки: [Next.js](https://nextjs.org/docs/app/getting-started/installation), [shadcn/ui и Tailwind v4](https://ui.shadcn.com/docs/tailwind-v4), [GitHub checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node), [upload-artifact](https://github.com/actions/upload-artifact).
