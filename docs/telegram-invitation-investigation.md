# Проверка приглашений Telegram — 31 октября 2026

## Подтверждённые наблюдения

- Собственный второй аккаунт администратора смог подтвердить и принять приглашение.
- Последовательные попытки другого пользователя дают `login_account_mismatch_other`, затем `login_subject_unknown`.
- Первый код означает, что подписанный Telegram `sub` сохранён у другого пользователя Supabase. Второй означает, что точного `sub` нет среди Telegram identities вообще. Это не доказывает, что человек сознательно выбрал другой аккаунт.
- Подпись, audience, issuer, nonce и срок токена прошли проверку до вызова функции привязки.
- Сохранённые `provider_id` совпадают с `identity_data.sub`; длина значений — 19–20 символов.
- Клиент и issuer локальной конфигурации совпадают с настройками провайдера Supabase; scopes — `openid profile`, attribute mapping пустой.
- Завершение единственного сеанса аккаунта Дарины не устранило ошибку. Сам аккаунт сохранён.

## Проверяемые причины

| Вариант | Что известно | Следующая проверка |
| --- | --- | --- |
| Число вместо строки в `id` | Оба формата поддерживаются; текущая ошибка возникает позже | Подписанные тестовые токены покрывают оба формата и недопустимые значения |
| Округление длинного `sub` | Наш код сохраняет его строкой; тест покрывает 20 цифр | Диагностика выявляет близкий, но не равный числовой subject; совпадение по близости никогда не даёт доступ |
| Другой аккаунт Telegram на шаге подтверждения | Возможен; прежний код сравнивал subject раньше получателя | Сначала сравнивается подписанный `id` с получателем ссылки бота |
| Другой аккаунт Family в браузере | Ранние попытки совместимы с этим вариантом | После совпадения получателя проверяется принадлежность subject текущему пользователю |
| Разные OAuth-клиенты/конфигурации | В локальной конфигурации и Supabase совпадают | Проверить production-конфигурацию отдельно, если получатель совпадёт, а subject останется неизвестен |
| Cookie, PKCE, nonce, подпись или срок токена | Текущие попытки проходят эти проверки | Эти ошибки имеют отдельные диагностические коды |
| Истёкшая ссылка бота | Её срок отличается от срока самого приглашения | Отдельные коды `handoff_expired` и `invitation_unavailable` |
| Старый код из GitHub | Последняя ошибка пришла из текущего прямого Vercel-деплоя | Сохранить проверенные изменения и миграции в Git перед следующим Git-деплоем |

## Следующий шаг

После публикации диагностики нужна одна попытка по свежей ссылке из бота:

- `recipient_mismatch`: Telegram на подтверждении отличается от получателя ссылки.
- `login_account_mismatch_other`: получатель совпал, но Family открыт под другой учётной записью.
- `login_subject_numeric_near`: получатель совпал, subject отличается от одного из сохранённых чисел не более чем на 4096; проверить источник преобразования, не менять привязки автоматически.
- `login_subject_unknown_recipient_matches`: получатель совпал, но точного subject нет; исследовать конфигурацию и поведение двух OIDC-потоков.

Диагностика доступна только `service_role`, возвращает категорию ошибки и не выдаёт идентификаторы. Правила привязки и вступления не ослаблены; username не используется для подтверждения владельца.

Проверки: 12 целевых unit/SQL-тестов, lint с архитектурными границами и production build прошли. Успешное вступление Дарины пока не подтверждено.
