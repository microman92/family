**Дата обновления:** 27 октября 2026 года. **Текущая цель:** создать полный семейный менеджер (быт + финансы), **без ИИ**, поэтапно.

## Главное изменение относительно ранней версии

Финансовая часть **больше не ограничена расходами на покупки**. В целевую V1 входят: счета/остатки, доходы и расходы, переводы, бюджеты, долги/кредиты/рассрочки, накопления, регулярные платежи, семейный календарь, напоминания, задачи, заметки, файлы, PWA и аналитика.

**ИИ специально исключён из V1**; отдельные future-идеи не реализовывать до нового решения. Банковское подключение и реальные платежи также не входят в текущий объём.

## Архитектура в двух словах

- **Frontend:** Next.js App Router, TypeScript strict, FSD `src/_app`, `src/_pages`, `widgets`, `features`, `entities`, `shared`.
- **Стилизация:** основная — SCSS Modules (`*.module.scss`) рядом с компонентами; компоненты shadcn/ui — Tailwind CSS. Общие CSS-переменные темы используются в обоих подходах; правила — в `SPEC.md` §10 и `AGENTS.md`.
- **Backend:** отдельные `src/server/modules/{domain,application,infrastructure}` с SOLID и тестируемыми use cases.
- **Auth и данные:** Supabase Auth и PostgreSQL с RLS — отдельные логины для каждого члена семьи, server-side family/private scope.
- **Деньги:** двойная бухгалтерская запись (ledger) и сторно; нет двойного подсчёта расходов при покупках, переводах, целях и долгах.
- **Стратегия:** большое приложение создаётся небольшими фазами со своими контрольными проверками.

## Принятые продуктовые допущения

- Один пользователь находится в одном семейном пространстве V1.
- Валюта V1 — UZS, timezone семейного пространства по умолчанию `Asia/Tashkent`.
- В одной семье общий финансовый учёт виден взрослым участникам, личные счета и заметки — только их владельцам.
- Не происходит фактических банковских списаний. Пользователь сам отмечает оплату.
- Web Push только при согласии; in-app напоминания обязательны.
- Офлайн-денежные операции запрещены; PWA поддерживает установку и безопасный offline fallback.

## Telegram и дни рождения

- Вход через Telegram, приглашение через ссылку на бота или QR-код, явное подтверждение вступления. Email/password остаётся дополнительным способом входа.
- Ссылку или QR администратор отправляет самостоятельно: Telegram не позволяет боту начать личный диалог только по нику получателя.
- Уведомления через бота приходят в подтверждённый Telegram-аккаунт входа при разрешении пользователя; in-app сохраняется всегда.
- При указании дня рождения доступны три напоминания: за 12 и за 2 часа до начала дня рождения, затем в сам день в 10:00. По умолчанию используется timezone семьи; каждое напоминание можно отключить. Например, для 15 ноября: 14 ноября 12:00 и 22:00, затем 15 ноября 10:00.
- Это согласованные требования; реализация и проверки остаются в фазах 2, 12, 16 и 17.

## Локальный запуск

Требуется Node.js 24 LTS и npm. В Windows PowerShell используйте `npm.cmd`, если системная политика блокирует `npm.ps1`.

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:3000. Для production-проверки: `npm run build`, затем `npm start`.

Без `.env.local` доступен гостевой каркас. Для разрабатываемого входа скопируйте `.env.example` в `.env.local` и укажите URL и publishable key своего Supabase; секреты никогда не добавляйте в Git. Публичный URL приложения настраивается через `NEXT_PUBLIC_APP_URL`. Фаза 2 пока не завершена: миграция, вход и RLS требуют проверки на настоящей Supabase-среде.

### Проверки

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

`lint` включает анализ циклов, FSD public API и серверных границ. Unit-тесты проверяют точность UZS и даты. Playwright проверяет маршруты, темы, навигацию, клавиатуру, узкие экраны и доступность axe. E2E автоматически поднимает свой production-сервер на порту 3107, поэтому сначала нужна сборка; другие локальные серверы не используются. На Windows тесты используют установленный Google Chrome с отдельным временным профилем; в Linux/CI установите браузер командой `npx playwright install --with-deps chromium`.

SQL-миграция проверяется в `npm test` на встроенном PostgreSQL PGlite с имитацией минимальной схемы Auth. Для приёмки фазы нужна дополнительная проверка на настоящем Supabase.

### Подключение Supabase и Telegram позже

Подключение сейчас не выполнялось. Для тестовой среды установите Docker, затем запустите `npx --yes supabase@2.122.0 start`: CLI применит локальные миграции. Скопируйте `.env.example` в `.env.local`, заполните URL и ключи локального Supabase из его статуса. Для внешней тестовой среды применяйте миграции только к выбранному dev/staging-проекту. Не передавайте секретные ключи в чат и не добавляйте `.env.local` в Git.

Для Telegram потребуется отдельный тестовый бот и публичный HTTPS-адрес приложения. В BotFather настройте OIDC и разрешите оба callback URL: `https://<supabase>/auth/v1/callback` и `https://<app>/auth/telegram-bind/callback`. В `.env.local` заполните Telegram и серверные ключи из `.env.example`; `NEXT_PUBLIC_APP_URL` должен совпадать с доверенным публичным адресом и разрешёнными адресами возврата Supabase.

После настройки можно вручную выполнить `npm run telegram:configure-provider` для создания OIDC-провайдера и `npm run telegram:configure-webhook` для регистрации webhook. Вторая команда заменяет ранее установленный webhook этого бота, поэтому используйте отдельного бота для разработки. Эти команды не запускаются автоматически. Работу входа, приглашений и RLS необходимо проверить на реальных тестовых аккаунтах.

Синхронизация HTML после изменения PRD/SPEC/TASKS: `python scripts/sync-documentation.py` (нужен `markdown-it-py`).
