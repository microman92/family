# Family Space — TASKS: поэтапный план разработки

> **Версия:** 2.0 · **Дата:** 26.10.2026 · **Цель:** весь функционал [PRD.md](PRD.md) и [SPEC.md](SPEC.md) в целевом V1, **без ИИ**.
> Назначение: самостоятельная разработка или последовательная работа AI-агента. Каждая фаза содержит завершённый проверяемый результат; ни один пункт не считается готовым без работающего кода и теста.

## 0. Общие правила исполнителя

1. Сначала прочитать **PRD → SPEC → TASKS** полностью; при конфликте: продуктовые требования — PRD, технические инварианты — SPEC, порядок — TASKS.
2. Выполнять фазы по порядку. Можно начать следующую только после прохождения **Gate** предыдущей; исключения фиксировать в `docs/adr/`.
3. Выполненная задача отмечается `[x]` только после проверки в реальном окружении; если проверка недоступна — оставлять `[ ]` и указывать причину.
4. **Не подменять реальную функциональность моками.** Демо/seed разрешены отдельно и с меткой demo. `TODO` в критичных потоках не считается реализацией.
5. Любая таблица с пользовательскими данными требует RLS, миграции, теста family/private и инвариантов scope **в той же фазе**.
6. Все денежные операции — атомарный balanced ledger, idempotency, audit, повторы без дублей. `BigInt/decimal-string`, не float.
7. SOLID: доменная логика вне React/Supabase SDK; FSD: публичные API и слои; DRY — общие контракты, не преждевременная генерализация.
8. В начале каждой фазы записать цель; в конце обновить `TASKS.md`, `CHANGELOG.md` и краткий отчёт: файлы/тесты/решения/риски.
9. Не удалять проведённую финансовую историю. Исправления через reverse/correction.
10. **НИЧЕГО ИИ в V1:** никакие LLM SDK, OCR/AI, модели, prompt endpoints и ключи не устанавливать.


## 0.2 Definition of Done для **каждой** задачи

- Код и миграции закоммичены и не ломают предыдущие сценарии.
- Критичная бизнес-логика покрыта тестом; изменения access scope — RLS tests.
- UI имеет loading/empty/error и понятную мобильную форму, без фальшивых кнопок.
- Использованы строгие типы и Zod входа; проверка auth на server.
- `lint`, `typecheck`, релевантные `tests`, `build` зелёные; блокеры явно зафиксированы.

## 20. Финальный обязательный сквозной сценарий V1

1. Муж зарегистрировался, создал семью, пригласил жену; у ребёнка есть ограниченный доступ.
2. Муж добавил в общий список молоко (план 28 000) и продукты (ближайшее/базар); жена увидела список.
3. Жена отметила частичную покупку на 30 000 сум; система создала ровно один расход, остался непроданный объём.
4. Пользователь добавил 1 000 000 сум дохода, перевёл 100 000 сум между счетами: остатки корректны, расход/доход не удвоен.
5. Настроен месячный бюджет «Продукты»; факты по покупкам и ручным операциям попали в ту же категорию.
6. Создан долг 500 000, возвращено тело 100 000 и проценты 5 000: основной остаток 400 000, обычный расход +5 000.
7. Создана цель «Отпуск», переведено 200 000 на savings: цель выросла, обычные расходы не изменились.
8. Создан ежемесячный платёж «Интернет»: до клика «Оплачено» нет expense, после подтверждения ровно один posted expense.
9. Добавлены событие, день рождения, повторяющаяся задача; сроки показаны календарём без дублей. Для дня рождения 15 ноября напоминания запланированы на 14 ноября 12:00/22:00 и 15 ноября 10:00 в timezone события; in-app и разрешённый Telegram-канал проверены с повторным запуском worker.
10. Работают напоминания in-app; Web Push только если разрешён; после ретрая один notification.
11. Личная заметка мужа и личный финансовый счёт остаются скрытыми для жены и admin другого аккаунта даже через API.
12. Исключённый участник не может запросить семейные данные; shared financial history не исчезает.
13. Работают 320px mobile UI, безопасный PWA fallback, demo seed/cleanup и экспорт разрешённых данных.
14. Все SQL RLS, unit, E2E, staging smoke тесты зелёные. Только тогда отмечать **V1 release done**.
